# Vue 日期前端

Vue 3 + Vite + Vue Router。需要 Node.js 20.19+ 或 22.12+。

## 本地启动

```bash
cd frontend
npm install
npm run dev
```

打开终端显示的地址（默认 http://localhost:5173）。

- `/`：显示页面加载时浏览器本地时区的日期，格式为 `YYYY/MM/DD`，跨午夜后刷新页面更新。
- `/2026/10/10`：显示 `2026/10/10`。
- `/:year/:month/:day`：支持其他有效日期，年份四位、月份和日期两位。
- 无效日期（例如 `/2026/02/30`）或其他路径显示提示。

顶部导航栏采用暖白与胡桃棕配色，左侧为 NOVI 品牌标识，右侧为首页入口与显示当前采集日期的日期按钮；小屏幕自动分为两行。默认高亮「首页」。点击「切换日期」展开日历，可切换月份，选择一天后跳转到同一站点的 `/YYYY/MM/DD` 页面；「回到今天」可直接打开当天日期页面。日期页面高亮「切换日期」，点击品牌标识或「首页」返回 `/`。点击日历外部或按 Esc 可关闭日历。

导航下方改为左侧问候区，取消居中的大日期展示。问候语按浏览器本地时间变化，正文说明今天的日期、星期、当前查看的采集日，以及该采集日 +30～+45 天的入住日期范围和周末天数。节假日提示暂用模拟数据：将采集日后第 35～36 天设为演示假期，页面明确标注「模拟」，并未接入真实节假日日历。切换采集日期后，入住范围和演示假期同步变化。

有效日期页面分为「自身酒店」和「其他酒店」两个分组。自身酒店为 NOVI Dotonbori；其他酒店包含住一，以及两个明确标注为示例的竞品酒店，待替换为实际酒店名称。酒店列表在 `src/views/DateView.vue` 的 `hotelGroups` 中配置，新增竞品时在 `competitors` 分组的 `hotels` 数组中添加唯一 `id`、`name` 和 `rooms` 即可。每家酒店均包含房型 A、房型 B 的相同价格模块。每个模块展示 Vue Data UI 多系列折线图和 K 线图，两图共用该房型的数据，各酒店、各房型独立生成模拟数据。以当前页面日期为采集日基准，横轴包含采集日后第 30～45 天（含首尾）的 16 个入住日期，格式为 `MM/DD`；每个入住日期有从采集日前 6 天至采集日、每天一次的 7 条采集记录，价格为 20000～40000 内的随机整数。小屏可横向滚动查看。

酒店列表上方新增酒店价格多柱状图：X 轴为入住日期，Y 轴为价格（从 0 起），每组柱子同时展示当前页面采集日所有酒店、所有房型的报价，图例使用「酒店 · 房型」标识，无需切换房型。采用陶土棕、鼠尾草绿、暖金和雾蓝配色，同一酒店使用同色系，深浅区分房型。悬停查看价格，点击图例隐藏或显示对应房型。柱状图与下方各酒店房型的折线图、K 线图共用数据；重新生成某个房型数据时同步更新。首页使用浏览器本地今天，日期页面使用选定日期；切换日期会重新生成对应采集日的模拟数据，尚未接入真实采集数据库。缺失报价留空。柱子加粗、日期组间距收紧，X 轴使用水平 MM/DD 标签；图表按房型数量保持足够宽度，可用鼠标左右拖动、触屏滑动或底部滚动条查看后续日期，键盘聚焦图表后也可用方向键滚动。Y 轴固定在左侧，左右滑动仅移动柱子与日期；价格刻度与横向网格线共用相同的比例，隐藏房型时保持刻度稳定。

## 验证与构建

折线图中当日采集为蓝色，其余 6 次采集为灰色。悬停提示展示入住日期、7 个采集日期及价格。K 线开盘价和收盘价均等于当日采集价，最高价和最低价取 7 次采集的极值；蓝色横线标识当日价格。点击“重新生成本房型数据”按钮同时刷新该模块内的两张图。实际每天采集 +30～+51 天的入住价格，连续运行 7 天即可为展示区间积累这些历史记录。

## 性能说明

图表在距离可视区域 200px 内时才初始化，避免首屏同时创建全部 17 张图表。已初始化的图表保留挂载，滚动离开再返回时保留图例等交互状态；不支持 `IntersectionObserver` 的浏览器会直接加载。价格数据仍统一生成、同步更新，未显示的图表首次进入视口时使用最新数据。

价格快照使用浅层响应式，重新生成房型数据时替换该房型及所属酒店的对象，避免为每个价格点创建响应式代理。当前时间仅在页面加载时获取一次，日期和问候语通过刷新页面更新，不设置每秒检查的定时器。

## AI 聊天窗


所有页面右下角提供「AI 聊天」按钮，点击展开聊天窗。支持连续对话、Enter 发送、Shift + Enter 换行、Esc 收起；收起后保留本次页面会话，刷新后清空。发送失败会保留问题供重新发送。

目前后端尚未实现聊天 API。接通时，将 `frontend/.env.example` 复制为 `frontend/.env.local`，设置 `VITE_CHAT_API_URL` 为你的后端聊天接口地址，再重启开发服务器或重新构建部署。未配置时，发送操作会提示服务尚未配置。

接口约定：`POST` JSON `{ "messages": [{ "role": "user", "content": "你好" }] }`，后续请求包含此前成功对话的 `user` / `assistant` 消息；返回 JSON `{ "answer": "AI 回复" }`。前端最长等待 60 秒。接口需通过同源反向代理或正确配置 CORS，AI 服务密钥仅保存在后端。当前聊天不自动读取页面图表或酒店数据库。

## Nginx 部署

构建产物位于 `dist/`。仓库提供 `nginx.conf` 站点配置，默认监听所有 IPv4 网卡的 80 端口，站点目录为 `/var/www/ai-hotel-assistant`。无需启动 Vite，也无需转发到 5173。

在安装了 Nginx 的 Linux 服务器上，从项目的 `frontend` 目录执行（构建产物也可在本地生成后上传）：

```bash
npm ci
npm run build
sudo mkdir -p /var/www/ai-hotel-assistant
sudo cp -R dist/. /var/www/ai-hotel-assistant/
sudo cp nginx.conf /etc/nginx/conf.d/ai-hotel-assistant.conf
sudo nginx -t
# 仅在检查成功后执行：
sudo systemctl reload nginx
```

此文件是 `server` 配置块，应由主配置的 `http` 块加载，不要用它覆盖 `/etc/nginx/nginx.conf`。若主配置没有加载 `/etc/nginx/conf.d/*.conf`，请在 `http` 块中加入对应的 `include`。

此配置使用 `listen 80 default_server;`，通过服务器 IPv4 地址访问时会命中本前端。若其他站点也为同一监听地址声明了 `default_server`，需移除其他站点的该标记，再执行 `nginx -t` 并重新加载，避免默认站点冲突。使用域名时，将 `server_name _;` 改为实际域名；修改站点目录时同步修改 `root`。

配置已包含 Vue Router History 模式回退规则，支持直接访问和刷新 `/2026/10/10` 等路径；HTML 每次重新验证，Vite 带哈希的静态资源长期缓存，缺失资源返回 404。
