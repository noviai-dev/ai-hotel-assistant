# 系统架构

采用模块化单体起步，按业务边界划分模块，避免首版引入微服务运维成本。

```text
Web Console / Guest Chat
          |
       FastAPI
          |
  +-------+----------+-----------+
  | Market | GEO     | Concierge |
  +-------+----------+-----------+
          |          |
   PostgreSQL   Adapter Layer
          |      LLM / PMS / OTA / CRM
          +------ Task Queue (later)
```

## 后端边界

- `market`: 市场快照、预订节奏、建议生成与审核
- `geo`: 品牌配置、问题集、巡检运行、提及/引用记录、报告
- `concierge`: 知识检索、会话、意图、工单、人工升级
- `integrations`: LLM、PMS、OTA、CRM、通知服务等可替换适配器
- `core`: 配置、鉴权、租户上下文、日志、错误处理

## 决策记录

- **模块化单体**：先降低部署复杂度，模块间通过服务接口交互。
- **建议与执行分离**：价格和对客动作先进入审核队列。
- **适配器模式**：尚未确定具体 PMS/OTA/LLM 服务，避免把供应商协议写入领域逻辑。
- **PostgreSQL**：保存酒店配置、审计记录和业务对象；向量检索可在知识库阶段选用 pgvector 或托管服务。
